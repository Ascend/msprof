# msprof 开发闭环

将“实现/修复/重构”类请求推进至可验证、可交付的状态。本 Skill 负责编排，远端写入复用 `gitcode-pr`，CI 复用 `gitcode-ci`；数据链路和输出契约按 `AGENTS.md` 第 6、7 节核对。

## 适用与不适用

适用：

- “实现 xxx 功能”“修复 xxx 问题”“重构 xxx”“补齐 xxx 测试”
- “按方案完成修改并执行验证”
- 需要跨多个文件、但目标单一的代码变更

不适用：

- 只读检视 PR：使用 [msprof-review](../msprof-review/SKILL.md)
- 已有检视意见的修复：使用 [msprof-review-feedback](../msprof-review-feedback/SKILL.md)
- 只查看或修复 CI：使用 [gitcode-ci](../gitcode-ci/SKILL.md)
- 单纯的 PR 描述更新：使用 [gitcode-pr](../gitcode-pr/SKILL.md)

## 前置读取

1. [AGENTS.md](../../../AGENTS.md)，重点看意图路由、源码路由、数据契约和验证矩阵。
2. 涉及解析器、字段、DB、CSV/Timeline 时，读 [AGENTS.md](../../../AGENTS.md) 第 6、7 节及对应的交付件/DB 参考文档。
3. 提交或创建 PR 前，读 [gitcode-precommit](../gitcode-precommit/SKILL.md) 和 [gitcode-pr](../gitcode-pr/SKILL.md)。

## 工作流

### 0. 固定工作区事实

```bash
git status --short --branch
git remote -v
git log --oneline --decorate -5
```

- 记录当前分支、未提交修改和未跟踪文件；不得覆盖用户工作区。
- 确认当前分支不是 `master`；需要新分支时从任务指定的基线创建。
- 已有未提交修改时，先判断是否与本次任务相关，再决定在其基础上继续还是隔离 worktree。

### 1. 澄清范围与验收

在写代码前确认，已知信息跳过，缺失时逐项询问：

- 触发入口：命令、接口、导出格式或数据标签是什么？
- 期望行为：输入、输出、边界和错误处理分别是什么？
- 影响面：是否改变 CSV 表头/列顺序、DB 表结构、Timeline 字段、公共接口或默认行为？
- 兼容性：是否需要兼容旧数据、旧版本 DB、level0/level1、Host/Device、单卡/多卡？
- 验证方式：用哪份最小数据、哪个 UT、是否需要 NPU 或构建环境？

如果请求缺少必要信息且无法从代码和文档推断，先提问，不猜测实现。

### 2. 定位职责链

按 [AGENTS.md](../../../AGENTS.md) 第 6 节选择入口，先读实现和相邻测试，再扩展搜索：

- 从命令入口、调度、解析器、关联计算、Model、Viewer/导出逐层确认数据流，优先复用同类实现和工具函数。
- 涉及 C++/Python 双路径时，检查准入、回退和错误上报语义；输出契约按 [AGENTS.md](../../../AGENTS.md) 第 7 节核对。

### 3. 输出方案与任务拆解

非小型改动先给出 2 至 3 个方案及取舍，说明推荐方案，等待用户确认。方案至少覆盖：

- 改动文件和数据流
- 输出契约变化
- 测试与验证方式
- 风险和未覆盖项

确认后拆成 3 至 8 个可独立验证的子任务，标明依赖顺序。会话内用待办列表跟踪；跨会话以 Issue/PR 评论为审计记录，不新建本地状态文件。

### 4. 实现

- 只做当前目标必需的最小改动，不额外重构无关代码。
- 修改前先读完整上下文，包括相邻类型、异常路径、资源清理和调用方。
- 新增行为或修复缺陷时补回归测试，复用相邻测试的数据、Mock 和断言风格。
- 不留调试打印、TODO、FIXME、硬编码路径；确需保留时说明原因并登记。
- 每完成一个子任务就运行最相关的检查，不批量假定完成。

### 5. 验证

按风险选择最低充分验证，具体命令和范围见 [AGENTS.md](../../../AGENTS.md) 第 8 节。数据链路改动还需用最小脱敏数据对比修改前后的 DB 表结构/行数/关键字段、CSV 表头与样例行、Timeline 事件和空值语义，并覆盖缺失、截断和旧版本数据等失败路径。

- 记录实际执行的命令和结果，不只写“测试通过”。
- 区分未运行、跳过、失败和通过；缺环境或数据时说明原因和残余风险。
- 修改 AI 资产后运行 `python3 scripts/ai/validate_skills.py`。

### 6. 提交与交接

- 远端写入按 [AGENTS.md](../../../AGENTS.md) 第 4 节确认授权；执行前报告变更摘要和验证证据。
- 提交信息使用 `feat:`、`fix:`、`docs:`、`refactor:`、`test:` 等类型，保持单一目标。
- 提交前按 [gitcode-precommit](../gitcode-precommit/SKILL.md) 检查 hooks，并核对 `git status` 和最终 diff。
- PR 创建或更新交给 [gitcode-pr](../gitcode-pr/SKILL.md)，提供验证证据和残余风险；创建后按用户目标决定是否进入 [gitcode-ci](../gitcode-ci/SKILL.md)，不在未授权时评论 `compile`。
- 独立检视不在本 Skill 范围内；需要时交给 [msprof-review](../msprof-review/SKILL.md)。

## 完成标准

- 目标行为已实现，且没有引入无关改动。
- 受影响测试、检查和构建已执行并通过，或明确记录未执行原因。
- 输出契约变化已同步配置、消费者、测试和文档。
- 最终 diff、`git status`、提交信息和 PR 正文一致。
- 交付说明包含：改了什么及原因、实际命令与结果、未覆盖项和残余风险。

## 停止条件

遇到以下情况暂停并交用户决策：

- 需求和现有实现、文档或数据契约冲突，无法从上下文判断。
- 需要改变公共行为、数据语义或兼容策略，但未获确认。
- 需要新增权限、凭据、外部服务或不可逆操作。
- 验证持续失败且无法定位根因，或环境/数据不可用。
- 用户要求绕过测试、质量门禁或强制推送。
